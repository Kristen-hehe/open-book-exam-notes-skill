# Source processing

Read only the sections needed for the supplied formats. Preserve source order and labels so results can be traced back to the material.

## Reference notes

Inspect the reference document before drafting:

- page size, margins, header/footer, page numbering;
- title hierarchy, body font, table styling, emphasis colours;
- recurring structures such as exam maps, formula tables, warnings, and worked answers;
- defects worth avoiding, including blank spill pages, clipped tables, and isolated headings.

Record a hash before authoring when the reference must remain unchanged.

## PDF lecture notes and sample exams

- Extract text for search, but render and inspect relevant pages because formulas, charts, diagrams, and question layout may not survive text extraction.
- For sample exams, capture question wording, marks, required outputs, datasets, and command verbs such as calculate, interpret, compare, recommend, or justify.
- Use the sample exam to set priority, not to assume that identical questions will appear.

## PowerPoint

- Extract slide text, tables, and speaker notes.
- Render slides that contain screenshots, trees, charts, formulas, or output tables; these often hold the most important evidence.
- Distinguish assignment instructions from the student's submitted answer and from lecturer commentary.

## Word documents

- Inspect paragraphs, headings, tables, headers/footers, and embedded images.
- When continuing an existing series, reuse its style and information architecture without carrying over unrelated course content.

## Spreadsheets and CSV files

- Preserve the raw source.
- Inspect sheet names, headers, formulas, named ranges, charts, and data types.
- Recalculate important statistics or model inputs when feasible. State units and the exact denominator for ratios such as CV, accuracy, or rates.
- If a workbook value conflicts with a slide, identify the discrepancy instead of silently selecting one.

## Workflow/project files

For files such as Orange `.ows`, inspect widget names, connections, saved settings, selected variables, validation design, and output roles. Convert the graph into a short operational sequence such as:

`File -> Select Columns -> Data Sampler -> Tree -> Test & Score -> Predictions`

Do not present a saved workflow setting as a universal best practice.

## Evidence map

Before writing, keep a compact private map with:

| Topic | Source | Exam relevance | Verified result | Caveat |
|---|---|---|---|---|

Use it to prevent omissions, duplicated explanations, and unsupported numbers. Do not place this internal map in the final note unless the user asks.
